# 执行计划入口 (AGENTS.MD)

本目录记录并管理项目的执行状态与技术债务。在 Harness Engineering 体系中，这里也是“代码库免疫系统 (Immune System)”的重要组成部分，用于对抗由于 Agent 开发带来的指数级熵增（技术债复制）。

## 核心理念：熵管理与代码库免疫系统

1. **防范技术债的指数级复制**: AI 极易将临时妥协当成“先例”进行系统性复制。必须建立强大的静态分析和 Linter 规则。
2. **垃圾回收 (Garbage Collection)**: 技术债是高息贷款。这里的 `tech-debt-tracker.md` 就像是系统熵的记录仪，我们必须定期发起清理这些债务的 PR。
3. **建立黄金规则**: 将正确的模式编码进仓库的测试和 Linter 中，而不仅是写在文档里。如果发现 Agent 在生成坏味道代码，必须立刻在 CI 层面上添加拦截规则。

## 目录结构

- `active/`: 当前正在执行的 Sprint 或计划。
- `completed/`: 已完成并归档的计划。
- `tech-debt-tracker.md`: 记录在开发过程中产生的妥协或不良模式，等待被重构或通过 Linter 规则根除。
