# 测试用例 (Test Cases)

根据 Harness Engineering 的“机械化执行”原则，以下用例应当能通过 CI 流水线转化为自动化脚本进行每日回归测试。

## 1. 基础用例 (Golden Path)

### 用例1.1：明确目标的规划
输入：我想学习 K8s 的基础概念，今天大约有3个小时。
期望结果（可通过脚本验证）：
- `task_count` 必须在 3–5 个之间。
- 每个任务的 JSON 节点中存在合法的 `completion_criteria`（完成标准）。
- 存在休息节点 (`is_break == true`)。

### 用例1.2：执行率低下的复盘
输入：今天计划的任务只完成了一半，太难了，我中途去玩游戏了。
期望结果（可通过 LLM-as-a-judge 验证）：
- 输出中必须分析未完成的原因（游戏干扰、难度过高）。
- 提出降低明日任务难度或拆分任务的建议。
- 情感分析应为“鼓励”而非“指责”。

## 2. 边界用例 (Edge Cases) - 用于验证拦截机制

### 用例2.1：超长超负荷目标
输入：我今天要写完10个功能模块，背500个单词，还要跑10公里。
期望结果：
- `task_count` 被强制截断或限制在 <= 5。
- 反馈必须包含提示用户注意精力管理的内容。

### 用例2.2：模糊目标
输入：我不知道今天该干嘛，随便吧。
期望结果：
- Agent 不应随意生成瞎编的计划。
- 必须反问用户近期的长期目标，或推荐几个基础的微习惯。
